# 建仓需求补充 v2：迁移后主体授权与凭证核验

本文件在原有键映射迁移能力之上增加一条独立业务工作流。原始 seed、既有题面及其源码契约保持原样；此补充只描述已实现的授权边界与验收。

## 业务对象与结论

旧系统把授权事件绑定到 `(table, old_key, principal, purpose)`；迁移后，访问请求使用新键。授权采信决定旧授权版本是否可用，访问裁定决定指定人员、用途和字段能否读取当前目标，凭证核验决定过去签发的访问凭证在撤销、目标更正或计划回滚后是否仍有效。对象是**主体×用途的访问权**与凭证，不裁决自然键碰撞，也不执行数据擦除。

## 首版合同

1. `auth-import` 保存来源原始字节与摘要。每个 `grant_id` 的主体、旧身份和用途不可变；同版本异文进入冲突，旧版本迟到保留历史而不覆盖现行事件。授权与撤销按带时区的生效时刻回放；字段必须显式列出。
2. `access-check` 通过 `identity_map` 找唯一旧身份，并要求对应计划已应用、目标行存在、最近的 `target_audit` 完整且摘要仍与当前目标及来源一致。授权字段须覆盖本次请求；无授权、已撤销、字段越界、版本冲突及审计过期分别给出可观察结论。请求 ID 和正文摘要冻结，旧请求失效后须用新请求 ID 重判。
3. `credential-issue` 只对当前允许的访问裁定签发随机凭证，数据库只存 token 摘要及授权版本、计划、目标载荷摘要和到期时间。`credential-verify` 每次重新核验映射、授权时间线、目标与审计；撤销判 revoked，更正或计划变更判 stale，过期判 expired。错误 token 不改变凭证状态，但留下失败核验记录。
4. `auth-report` 从持久实体重建授权批次、事件、冲突、访问裁定、凭证状态与检查历史，不输出 token 明文。跨模块更新不抹去原始事件或旧裁定证据。

## 运行与验收

`python -m keybridge demo-auth` 在合成父子迁移上完成目标核对、授权导入、访问允许、凭证签发、撤销后凭证拒绝。`python -m pytest -q tests/test_authorization.py` 覆盖正常、同版本冲突、迟到事件、字段越界、撤销与重新授权、目标更正后新审计、计划回滚、错误 token、到期与幂等。真实身份认证、密钥托管、跨进程凭证分发不在本地模拟器范围内。
